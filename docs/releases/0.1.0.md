# ChatGPT Web Gateway 0.1.0 preview

First independently versioned project release. English-first, file-configured
OpenAI-compatible gateway with client-owned function tools, MCP and Codex flows.

## Included

- Chat Completions and Responses, typed SSE, strict client-tool validation and
  bounded recovery; explicit web/native model routes.
- Codex Shell/patch workflows, client-side stdio/HTTP MCP, app-server,
  response continuation and optional WebSocket within documented limits.
- File-based credentials, deployment/rollback guides, community reporting forms
  and reproducible offline checks.

## Install

Prepare `.env` and `data/token.txt` using the README, then:

```sh
docker compose -f compose.yaml -f compose.release.yaml pull gateway
docker compose -f compose.yaml -f compose.release.yaml up -d --no-build gateway
```

The registry reference is `ghcr.io/pythc/chatgpt-web-gateway:v0.1.0`.
The publication receipt below supplies its immutable digest and source commit.

## Validation and boundaries

The release workflow tests both image architectures without model access.
The qualified baseline's 288 offline tests cover gateway behavior. Real model
acceptance is inherited from baseline `302fe48`; this release does not claim a
new live-model run. The compatibility matrix records exact client scope.

Web tools use a validated text bridge; complete tool frames are buffered before
emission. Web compaction summarizes context; native opaque state is separate.
No full official API parity, hosted tools on web, account availability or quota
recovery is promised. Clients retain execution permissions and approvals.

## Migration / rollback

The version string changes from upstream `1.8.8-beta2` to project `0.1.0`.
No new runtime state migration is introduced. Preserve `.env`, `data/`, mounts
and your previous image digest. The former account-management HTTP routes are
removed; credential changes now require editing the file and restarting.
See the configuration and release guides before rolling back to older images.
